# HTML validation

Pannonico validates final generated HTML in memory after directive-selected Pro
CSS inlining or Free directive removal, the directive-free output audit, and
optional HTML beautification or minification. There is no earlier HTML
validation pass before those transforms. Directive syntax has its own earlier
preflight and is documented in [`directives.md`](../authoring/directives.md). Validation
does not modify generated bytes and does not sanitize HTML.

## Modes

`validation.html` accepts:

- `off`: skip all built-in HTML checks;
- `warn`: emit warnings and keep the dry run successful;
- `error`: emit errors and fail the dry run.

The default is `warn`. `pannonico build --html-validation` uses the same values.

## Checks

Every rendered page must contain at least one non-whitespace byte and valid
UTF-8. NUL characters are rejected before parsing. A document structure that
exceeds the parser's supported nesting depth becomes `HTML_PARSE_FAILED`
instead of terminating the build process.

Pannonico parses accepted input into a WHATWG document tree with
`golang.org/x/net/html`. The parser repairs ordinary HTML syntax errors. It is
not a conformance validator, linter, or sanitizer.

Full documents are rendered bytes that contain an authored `<html>` start tag.
They must also contain:

- an HTML doctype, such as `<!doctype html>`;
- a `<title>` with non-whitespace text.

The parser inserts `html`, `head`, and `body` nodes when it parses a fragment.
Pannonico detects the authored start tag separately, so a `layout: none`
fragment does not receive false missing-doctype or missing-title findings.

Every exact non-empty `id` value must be unique in the parsed document. ID
comparison does not trim whitespace or fold case. A value repeated two or more
times produces one deterministic diagnostic.

## Diagnostics

Validation findings use the rendered page source path. The HTML parser does
not retain source offsets, so line and column are unavailable. Diagnostics are
sorted by the shared deterministic ordering contract.

Validation findings use these stable codes:

- `HTML_OUTPUT_EMPTY`;
- `HTML_INVALID_UTF8`;
- `HTML_NULL_CHARACTER`;
- `HTML_PARSE_FAILED`;
- `HTML_DOCTYPE_MISSING`;
- `HTML_TITLE_MISSING`;
- `HTML_DUPLICATE_ID`.

Template parsing and execution failures remain `TEMPLATE_*` diagnostics and
are not reclassified as HTML validation findings.
